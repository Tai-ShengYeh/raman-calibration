1. 為什麼食品營養系要學這個？

拉曼光譜儀是食品科學的好幫手：例如食用油摻偽初篩[9]、蛋白質結構研究、藥品與食品添加物篩檢……但機器吐出來的只是一堆數字。能讀懂、整理、甚至搶救這些數字的人，在職場上就多一把利器。這些應用仍須由適當的標準物、驗證樣本與方法效能資料支持，不能只靠一張「看起來很像」的譜圖下結論。

這門課用一個真實發生的狀況當教材：

研究助理用拉曼光譜儀量了鑽石和一份標示為萘（naphthalene）的固體樣品。回家打開檔案才發現——鑽石檔案的橫軸壞掉了，不是標準的波數，而是一串 0、1、2、3…的編號。幸好萘的檔案是好的。我們能不能借萘的資料，把鑽石遺失的座標算回來？市售防蟲丸也可能是對二氯苯或其他成分，未經標示／證書或獨立鑑別不能一律當作純萘標準。

答案是：可以，而且只需要國中程度的代數 + 十行程式碼。

2. 三分鐘認識拉曼光譜

把雷射打在樣品上，絕大多數光子以幾乎不變的能量散射（瑞利散射）；但極少數光子會和樣品的分子或晶格振動交換能量——這叫拉曼散射（Raman scattering）。入射光與散射光的能量差通常以拉曼位移（Raman shift，單位 cm⁻¹）表示，對應樣品允許的振動模態。

所以：一組峰的位置、形狀與相對強度可形成分子或晶體的光譜指紋；定性時應比對整體圖樣與量測條件，而不是看到單一峰就直接定案。

樣品結構特色特徵峰
鑽石四面體共價晶格；理想晶體的一階拉曼光譜以單一強峰為主約 1332 cm⁻¹[8]；應力、溫度、粒徑與雷射加熱都可能使峰位或峰寬改變
萘丸（萘）兩個稠合苯環，具有多個振動模態本課實測可見約 394、514、764、1021、1146、1380、1464、1577、3057 cm⁻¹；校正應使用有來源與不確定度的標準值[1]

3. 發現問題：鑽石檔案怪怪的

打開兩個文字檔的前幾行，長相完全不同：

第一欄（橫軸）第二欄診斷
naphethelene_….txt77.3545, 80.4019, 83.4475 … 3806.08光強度✔ 校正後的波數
dimond_….txt0, 1, 2, 3 … 2047（整整 2048 個整數）光強度✘ 只是偵測器像素編號

原來拉曼光譜儀的心臟是一片 CCD 感光晶片，上面有 2048 個像素排成一列。不同波長的光落在不同像素上。儀器軟體裡有一條「像素 → 波數」的換算公式，匯出資料時可以選擇要不要套用。量萘丸時有套用，量鑽石時不知道為什麼沒套——於是我們只拿到原始編號。

如果照著檔案字面解讀，鑽石的最強峰出現在「471」。但 471 cm⁻¹ 不是鑽石、也不是任何常見物質的指紋——真正的鑽石應該在 1332 cm⁻¹。資料沒有壞，只是地址寫錯了。

4. 解題發想：萘丸就是那把尺

關鍵觀察：兩批資料都有 2048 列。同一台儀器、同一片 CCD——萘丸資料的第 k 列和鑽石資料的第 k 列，來自同一個像素。

先確認才可沿用：兩檔必須使用相同雷射波長、光柵位置、狹縫／光纖、偵測器 ROI、binning、裁切範圍與像素方向。只有「同為 2048 列」並不足以證明逐列對應；若儀器設定或光路在兩次量測間改變，應重新量測有認證值的標準物，而不是直接複製舊座標。

5. 數學模型：多項式迴歸

我們想找一條通過所有（像素, 波數）點的平滑曲線。最常用的選擇是多項式：

波數 ≈ a₀ + a₁·x + a₂·x² + a₃·x³ 　　（x = 像素編號）

符號說明：x 是像素編號（無單位）；輸出是拉曼位移（cm⁻¹）；a₀ 是截距（cm⁻¹），a₁、a₂、a₃ 分別把 x、x²、x³ 換成 cm⁻¹ 的係數。這個公式只在本次參考資料涵蓋的像素範圍內使用，不應外插。

「迴歸」就是請電腦自動調整 a₀～a₃ 四個係數，讓曲線盡量貼近 2048 個資料點。多項式是常見的像素—波數轉換方法[2]，但幾次方要選多高必須依儀器與參考峰分布驗證。本資料的比較如下：

多項式次數形容全曲線最大誤差代入 x = 471判定
1 次（直線）y = a₀+a₁x378 cm⁻¹1285.7差 45，不行
2 次（拋物線）+ a₂x²60 cm⁻¹1305.8差 25，仍不夠
3 次+ a₃x³< 0.01 cm⁻¹1331.0完美貼合

初學者心法：次數太低 → 曲線太硬，彎不過來（underfitting，欠擬合）；次數太高 → 曲線追著雜訊跑（overfitting，過度擬合）。本案例三次式的殘差很小，所以可作教學重建；正式校正還應把部分參考峰暫時留出，檢查模型能否預測沒參與擬合的峰。研究也顯示物理模型在參考峰範圍外可能比多項式可靠[4]。

6. Python 實作

只需要一個套件 NumPy（安裝：pip install numpy）。整段程式只做三件事：讀檔 → 找公式 → 代入。

diamond_calibration.py 
# ===== 第 1 步：讀取萘丸資料（它有校正好的波數）=====
import numpy as np                          # 匯入數值計算工具箱，取名 np

data = np.loadtxt("naphethelene_100mW_1000ms_avg5_1.txt")  # 讀兩欄文字檔 → 二維陣列
wavenumber = data[:, 0]                     # 第 0 欄 = 波數（校正過的）
pixel      = np.arange(len(wavenumber))    # 自己編號：0,1,2,…,2047

# ===== 第 2 步：找出「像素 → 波數」的公式 =====
coef = np.polyfit(pixel, wavenumber, 3)    # 三次多項式迴歸，回傳 4 個係數
print(coef)
# [ 1.40578532e-07 -8.87048888e-04  3.04828977e+00  7.73547341e+01 ]

# ===== 第 3 步：把公式套到鑽石檔案 =====
dia   = np.loadtxt("dimond_100mW_1000ms_avg5.txt")
chan  = dia[:, 0]                           # 鑽石的第 0 欄只是通道編號！
sig   = dia[:, 1]

peak_chan = chan[np.argmax(sig)]            # 最亮的位置 → 471
peak_wn   = np.polyval(coef, peak_chan)     # 代入公式 → 1331.0
print(f"鑽石最強峰：通道 {peak_chan:.0f} ≈ {peak_wn:.1f} cm⁻¹")
# 鑽石最強峰：通道 471 ≈ 1331.0 cm⁻¹  ← 和文獻值 1332 只差 1！

逐行白話解析

程式碼它在做什麼
data[:, 0]「取所有列的第 0 欄」。逗號前是列範圍（空 = 全部），後面是欄位。
np.arange(n)產生 0, 1, 2, … , n−1 的編號清單，等於自己動手做「像素欄」。
np.polyfit(x, y, 3)最小平方法找三次曲線，回傳 [a₃, a₂, a₁, a₀]（注意：由最高次往前列！）
np.polyval(coef, 471)把 471 代進多項式求波數，等價於手算 a₃·471³+a₂·471²+…
np.argmax(sig)回報最大值「在第幾個位置」——用來找最強峰。

7. R 實作

偏好 R 的同學，用內建的 lm() 就能做一模一樣的事，連套件都不用裝：

diamond_calibration.R 
# ===== 第 1 步：讀取萘丸資料 =====
naph <- read.table("naphethelene_100mW_1000ms_avg5_1.txt")
colnames(naph) <- c("wavenumber", "intensity")
naph$pixel <- 0:(nrow(naph) - 1)           # 加上像素編號欄 0~2047

# ===== 第 2 步：三次多項式迴歸 =====
fit <- lm(wavenumber ~ poly(pixel, 3, raw = TRUE), data = naph)
summary(fit)                                # R² ≈ 1.000，殘差 < 0.01 cm⁻¹

# ===== 第 3 步：預測鑽石最強峰的波數 =====
dia <- read.table("dimond_100mW_1000ms_avg5.txt")
peak_chan <- dia [which.max(dia$V2), 1]    # 最亮列的通道編號 → 471
predict(fit, data.frame(pixel = peak_chan))
#        1
# 1331.007   ← 與 Python 完全一致！
R 函數對應的 Python說明
read.table()np.loadtxt()讀空白分隔的文字表格
lm(y ~ poly(x,3,raw=TRUE))np.polyfit(x,y,3)多項式迴歸（raw=TRUE 表示用 x³ 本身，而非正交多項式）
predict(fit, newdata)np.polyval(coef,x)帶入新值做預測
which.max(v)np.argmax(v)最大值的位置

語言不同，數學相同。兩邊算出的四個係數到小數第六位都一樣——這也是很好的自我檢查：如果你的 Python 和 R 結果不一致，一定是哪裡讀錯檔或設錯參數。

8. Excel 實作（不寫程式也能做！）

很多同學沒有安裝 Python 或 R，但幾乎每台電腦都有 Microsoft Excel（或 Google Sheets、LibreOffice Calc）。好消息是：同樣的三次多項式迴歸，在 Excel 裡用內建函數就能完成，完全不用寫程式。

適用場景：資料量不大（≤ 幾千列）、只需要做一次性校正或驗證時，Excel 是最快上手的工具。如果你之後要自動化處理上百份檔案，再轉 Python/R 即可。

Step 0：匯入資料

把萘丸的 naphethelene_100mW_1000ms_avg5_1.txt 匯入 Excel：

步驟操作
1開啟 Excel → 資料（Data）→ 從文字/CSV（From Text/CSV）
2選取檔案 → 分隔符號選「空格」或「Tab」→ 載入
3結果：A 欄 = 波數（2048 列），B 欄 = 光強度

在 C 欄手動建立像素編號：C1 輸入 0，C2 輸入 1，然後選取 C1:C2 往下拖到 C2048（或用公式 =ROW()-1）。

Step 1：用 LINEST 做三次多項式迴歸

LINEST 是 Excel 內建的最小平方法迴歸函數，只要把 x² 和 x³ 欄位準備好，它就能一次算出所有係數。

儲存格公式說明
D1（x²）=C1^2像素編號的平方，往下填滿到 D2048
E1（x³）=C1^3像素編號的三次方，往下填滿到 E2048

接著在空白區域（例如 G2:J2），選取四格橫排，輸入陣列公式：

' 選取 G2:J2 四個儲存格後，輸入以下公式'
' 然後按 Ctrl+Shift+Enter（舊版 Excel）'
' 或直接按 Enter（Microsoft 365 / Excel 2021+）'

=LINEST(A1:A2048, C1:E2048, TRUE, TRUE)

LINEST 會回傳由高次到低次的係數，和 Python 的 np.polyfit 順序相同：

G2H2I2J2
a₃ ≈ 1.406×10⁻⁷a₂ ≈ −8.870×10⁻⁴a₁ ≈ 3.0483a₀ ≈ 77.355
這四個數字應該和 Python / R 的結果完全一致（到小數第六位）

Google Sheets 也一樣：Google Sheets 的 LINEST 語法完全相同，而且不需要按 Ctrl+Shift+Enter，直接 Enter 就好。LibreOffice Calc 則需要先選取範圍再按 Ctrl+Shift+Enter。

LINEST 第二列以下的輸出（進階統計）

如果你選取的範圍是 G2:J6（五列四欄），LINEST 會額外輸出：

列內容意義
第 2 列各係數的標準誤差係數估計的不確定度
第 3 列R² 和 SyR² ≈ 1.000 表示擬合幾乎完美
第 4 列F 統計量、自由度整體迴歸顯著性
第 5 列迴歸平方和、殘差平方和變異拆解

Step 2：用係數算鑽石的波數

已知鑽石最強峰在通道 471，直接在任意儲存格輸入公式：

' 假設係數在 G2:J2（a₃, a₂, a₁, a₀）'

=G2*471^3 + H2*471^2 + I2*471 + J2

結果：≈ 1331.0 cm⁻¹　✔ 和 Python / R 完全一致！

想一次換算整條鑽石譜？把鑽石檔案也匯入，假設通道編號在 K 欄（K1=0, K2=1, …, K2048=2047），那在 L 欄用拖曳公式：=G$2*K1^3 + H$2*K1^2 + I$2*K1 + J$2，往下拖到 L2048，就得到全部 2048 個波數。

Step 3：驗證——用圖表視覺化

Excel 內建的趨勢線功能也可以直接驗證結果：

步驟操作
1選取 C1:C2048（像素）和 A1:A2048（波數），插入散佈圖（XY Scatter）
2在圖上右鍵點資料點 → 新增趨勢線（Add Trendline）
3類型選多項式，次數設 3
4勾選「在圖表上顯示方程式」和「顯示 R² 值」

圖上會直接秀出方程式和 R² ≈ 1.000。你可以把顯示的係數和 LINEST 的結果對照，確認一致。

注意精度：趨勢線預設只顯示到小數幾位，係數可能看起來被四捨五入了。LINEST 的結果才是完整精度，趨勢線主要用來做視覺驗證。做校正計算時，請用 LINEST 回傳的儲存格參照（例如 G2），不要手動抄趨勢線上的數字。

Step 4：另一種快速做法—— TREND / 查表

如果你只是要查「某個通道對應的波數」，不需要自己組公式，可以直接借用萘丸表格：

方法公式說明
直接查表=INDEX(A:A, 472)通道 471 是第 472 列（因為從 0 開始），直接回傳該列的波數
TREND 線性插值=TREND(A1:A2048, C1:C2048, 471)用線性迴歸做預測（只有一次方，精度不如三次式）

直接查表在通道為整數時最快，而且沒有迴歸誤差。但如果你想查通道 471.5（峰位落在兩個像素之間），就需要用多項式公式計算。

10. 驗證：答案對不對？

科學不能只信一個算法，我們用了三道獨立證據交叉確認：

#證據結果
1萘丸校正曲線換算：通道 4711331.0 cm⁻¹
2教科書文獻值：鑽石一階拉曼峰1332 cm⁻¹（偏差 −1）
3事後用雷射功率 50 mW 重新量測，並確認匯出時勾了波數校正（另兩個新檔案）1331.35 cm⁻¹

三個數字彼此差距都在 1 cm⁻¹ 內，並通過本課事先設定的 ±4 cm⁻¹ 示範允收帶——結果支持那顆「471」為鑽石的一階 Raman 峰[8]。±4 cm⁻¹ 不是所有 785 nm 儀器的共同規格；正式判定應採用該儀器製造商規格、實驗室 SOP 與標準物不確定度。

順手的加碼檢查：把萘丸自己的實測特徵峰跟可靠參考值比一比（764→762.4、1380→1379.1、1577→1576.6、3057→3056.4……），在本課示範允收帶內，代表這批資料沒有明顯的大幅波數錯位。

獨立性提醒：萘丸舊波數軸與用它換算的鑽石峰共享同一座標來源；較強的驗證是另量未參與擬合的標準物、保留參考峰做預測檢查，並在不同日期重複量測。ASTM E1840 提供可用於檢查波數軸的 Raman shift 值，但不提供完整儀器校正程序[1]。

11. 實戰體檢：用乙醯胺酚驗證校正

劇情接續：第 6～8 節我們用萘丸重建了「像素 → 波數」的三次公式（Python、R、Excel 三條路），也換回了鑽石的 1331 cm⁻¹。但校正過的東西一定要定期體檢——雷射會老化、溫度會漂移，昨天的公式今天還準嗎？這一節請出另一位主角：乙醯胺酚（Acetaminophen，普拿疼的主成分）。

為什麼挑乙醯胺酚當「體檢試劑」？

全譜中位數基線約 270 counts，純雜訊區（3600 cm⁻¹ 以上）標準差 σ ≈ 18 counts。知道「本底」之後，就能先訂一個可重現的教學找峰規則：

ace_find_peaks.py 
import numpy as np
from scipy.signal import find_peaks

spec = np.loadtxt("Acetaminophen_200mW_1000ms_avg5_0827_2026_1.txt")
wn, sig = spec[:, 0], spec[:, 1]

noise = sig[wn > 3600].std()              # 純雜訊區估 σ ≈ 17.6 counts
pk, _ = find_peaks(sig,
        prominence=8*noise,               # 凸出量至少 8σ 才算峰
        distance=8)                       # 相鄰峰至少隔 8 個通道
print(np.round(wn[pk], 1))
# [ 216   391   650   797   857   967  1014 … 1613  1649 ] 共 26 座峰

這裡的 8σ、distance = 8 是本資料的示範參數，不是通用標準。峰位也受訊噪比、峰形、解析度與擬合函數影響；跨實驗室研究建議用於校正的 Raman 峰應具有很高的 SNR，並明確記錄峰擬合方法[5]。

15. 重點整理與練習

三大重點

① 拉曼光譜的橫軸是「波數」，但機器底層其實只認得像素編號，中間靠一條校正公式連接。
② 在確認兩檔使用同一台儀器與完全相同光學／偵測器設定後，可用已知像素—波數對照重建座標；三次多項式只是本案例表現良好的模型。
③ 驗證要用互相獨立的證據：本課以乙醯胺酚建模，再用萘與 PS 驗證；驗證資料不可回頭調係數。

看答案得到 1285.7，低估 45 cm⁻¹。雖然仍看得出「大概在一千三百附近」，但在光譜學中 45 cm⁻¹ 誤差足以把石英（464）誤判成其他礦物，不足以作定性結論——模型選擇很重要。

Q3.（挑戰）不改校正曲線，改用另一招驗證鑽石峰：把換算後的整條鑽石譜圖畫出來，除了 1331 的主峰外你還觀察到什麼？（提示：注意 500–2000 區間的背景強度變化。）

看答案主峰之外只剩起伏很小的雜訊（約 ±100 counts），沒有任何其他拉曼峰——這正是鑽石「只有一種振動模式」的表現，也再次排除「混到別的物質」的可能。
